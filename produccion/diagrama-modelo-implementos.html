¿Es factible generar el historial por petición desde ASIGNACION_DETALLE en vez de una tabla física?

Sí, es 100% factible y es la mejor práctica de arquitectura relacional:
• Cero Redundancia de Datos: Cada fila en ASIGNACION_DETALLE ya almacena cuándo se entregó, a quién, cuándo se devolvió, el estado en que retornó (Excelente, Deteriorada, Perdida) y la observación de lo ocurrido. Tener una tabla HISTORIAL duplica exactamente la misma información.
• Consistencia Garantizada: No hay riesgo de desincronización entre lo que pasó en el préstamo y lo que dice el historial.
• Historial On-Demand: Cuando el frontend solicita GET /api/implementos/{id}/historial, el backend ejecuta un JOIN indexado que responde en menos de 1 milisegundo.
• Eventos Administrativos de Almacén: Si un implemento se daña o se da de baja dentro de bodega (sin operario), se actualiza directamente IMPLEMENTO.estado_actual y IMPLEMENTO.observacion_estado.

TIPO_IMPLEMENTO Maestro

Catálogo de categorías de herramientas. Permite agregar nuevos tipos dinámicamente sin modificar código ni base de datos.

id_tipo_implemento PK
nombre VARCHAR(100) (Tijera, Pesa)
prefijo_codigo VARCHAR(10) (TIJ, PES, CAL)
icono VARCHAR(10) (Emoji / Ícono)
IMPLEMENTO Activo Físico

Cada ítem físico individual inventariado. Mantiene su estado en tiempo real y la observación de almacén.

id_implemento PK
codigo_inventario UNIQUE (Tijera 1)
fk_id_tipo_implemento FK
estado_actual Disponible | Asignado | Deteriorada | Perdida
observacion_estado VARCHAR(255) (Bajas en almacén)
ASIGNACION_CABECERA Transaccional

Representa el acto de entrega múltiple a un operario en un turno específico por un supervisor responsable.

id_asignacion PK
dni_operario Receptor
fecha_hora_entrega TIMESTAMP
estado_asignacion Activa | Finalizada
ASIGNACION_DETALLE Historial Natural

Cada ítem entregado. Al devolverse, registra la hora exacta, el estado y las observaciones. Al consultarlo por implemento genera la trazabilidad completa.

id_detalle PK
fk_id_implemento FK
fecha_hora_devolucion TIMESTAMP (NULL = En uso)
estado_devolucion Excelente | Deteriorada | Perdida
observacion_devolucion TEXT (Melladura, daño, etc.)

Script SQL DDL + Vista de Historial On-Demand

-- =========================================================================
-- SAFCO - ARQUITECTURA DE DATOS: CATÁLOGO Y ASIGNACIÓN DE IMPLEMENTOS
-- Modelo Normalizado (Cero Redundancia de Historial - Sin Calibración)
-- =========================================================================

-- 1. TABLA: TIPO DE IMPLEMENTO (Maestro de categorías)
CREATE TABLE tipo_implemento (
    id_tipo_implemento SERIAL PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL UNIQUE,
    prefijo_codigo VARCHAR(10) NOT NULL,
    icono VARCHAR(10) DEFAULT '🔧',
    activo BOOLEAN DEFAULT TRUE
);

-- 2. TABLA: IMPLEMENTO FÍSICO (Inventario individual)
CREATE TABLE implemento (
    id_implemento SERIAL PRIMARY KEY,
    codigo_inventario VARCHAR(50) NOT NULL UNIQUE,
    fk_id_tipo_implemento INT NOT NULL REFERENCES tipo_implemento(id_tipo_implemento),
    estado_actual VARCHAR(20) NOT NULL DEFAULT 'Disponible', -- 'Disponible', 'Asignado', 'Deteriorada', 'Perdida'
    observacion_estado VARCHAR(255), -- Motivo si se deterioró o anuló en almacén
    fecha_registro DATE DEFAULT CURRENT_DATE,
    activo BOOLEAN DEFAULT TRUE
);

-- 3. TABLA: ASIGNACIÓN CABECERA (Entrega agrupada por operario)
CREATE TABLE asignacion_cabecera (
    id_asignacion SERIAL PRIMARY KEY,
    dni_operario VARCHAR(20) NOT NULL,
    fk_id_usuario_entrega INT NOT NULL,
    fecha_hora_entrega TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    observacion_entrega VARCHAR(255),
    estado_asignacion VARCHAR(20) DEFAULT 'Activa' -- 'Activa', 'Finalizada'
);

-- 4. TABLA: ASIGNACIÓN DETALLE (Items entregados y registro natural de devolución)
CREATE TABLE asignacion_detalle (
    id_detalle SERIAL PRIMARY KEY,
    fk_id_asignacion INT NOT NULL REFERENCES asignacion_cabecera(id_asignacion) ON DELETE CASCADE,
    fk_id_implemento INT NOT NULL REFERENCES implemento(id_implemento),
    fecha_hora_devolucion TIMESTAMP NULL, -- NULL mientras esté en uso
    estado_devolucion VARCHAR(20) NULL,   -- 'Excelente', 'Deteriorada', 'Perdida'
    observacion_devolucion VARCHAR(255),  -- Motivo del daño o nota al devolver
    fk_id_usuario_recepcion INT NULL
);

-- ÍNDICES DE ALTO RENDIMIENTO
CREATE INDEX idx_detalle_implemento ON asignacion_detalle(fk_id_implemento, fecha_hora_devolucion);
CREATE INDEX idx_cabecera_operario ON asignacion_cabecera(dni_operario, fecha_hora_entrega DESC);
CREATE INDEX idx_implemento_estado ON implemento(estado_actual);

-- =========================================================================
-- VISTA SQL: HISTORIAL DE TRAZABILIDAD ON-DEMAND (Generado por Petición)
-- Esta vista evita duplicar datos y responde a la petición del endpoint:
-- GET /api/implementos/:id/historial
-- =========================================================================
CREATE OR REPLACE VIEW v_historial_implemento AS
SELECT 
    d.fk_id_implemento,
    i.codigo_inventario,
    t.nombre AS tipo_implemento,
    c.id_asignacion,
    c.fecha_hora_entrega,
    c.dni_operario,
    op.nombres_completos AS operario_nombre,
    c.fk_id_usuario_entrega,
    d.fecha_hora_devolucion,
    CASE 
        WHEN d.fecha_hora_devolucion IS NULL THEN 'En Uso (Actual)'
        ELSE COALESCE(d.estado_devolucion, 'Devuelto')
    END AS estado_evento,
    d.observacion_devolucion,
    d.fk_id_usuario_recepcion
FROM asignacion_detalle d
INNER JOIN asignacion_cabecera c ON d.fk_id_asignacion = c.id_asignacion
INNER JOIN implemento i ON d.fk_id_implemento = i.id_implemento
INNER JOIN tipo_implemento t ON i.fk_id_tipo_implemento = t.id_tipo_implemento
LEFT JOIN vista_operarios op ON c.dni_operario = op.dni;
